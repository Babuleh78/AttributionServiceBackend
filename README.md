# Лабораторная работа 2

## Задание
Разработать структуру БД PostgreSQL и интегрировать ее с веб-приложением. Реализовать операции через ORM и прямой SQL.

## Основные требования
- **4 таблицы БД**: услуги, заявки, связь м-м, пользователи
- **5 статусов заявок**: черновик, удалён, сформирован, завершён, отклонён
- **ORM** для основных операций (получение, поиск, добавление)
- **Прямой SQL** (UPDATE) для логического удаления заявок
- **Интеграция** с существующими шаблонами из ЛР1

## Ключевые функции
 Поиск и просмотр услуг через ORM
 Добавление услуг в заявку-черновик (автосоздание при отсутствии)
 Просмотр состава заявки
 Логическое удаление заявок через SQL UPDATE
 Валидация: 1 черновик на пользователя

## Технологии
- **БД**: PostgreSQL в Docker
- **Backend**: Django ORM / Go + gORM
- **Панель администрирования**: Django Admin / Adminer
- **Миграции**: автоматические/ручные

## Структура БД
```
Услуги (id, название, описание, статус, url_изображения, ...)
Заявки (id, статус, дата_создания, создатель, дата_формирования, ...)
Заявки-Услуги (id_заявки, id_услуги, количество/порядок, ...) - составной UK
Пользователи (использовать системную таблицу)
```

## API endpoints
- `GET /` - список услуг (поиск через ORM)
- `GET /service/<id>` - детали услуги
- `GET /order/<id>` - просмотр заявки
- `POST /order/add-service` - добавление услуги в заявку (ORM)
- `POST /order/delete` - логическое удаление заявки (SQL UPDATE)

## Критерии оценки
 Корректная ER-диаграмма (StarUML)
 Работа с БД через ORM и прямой SQL
 Логическое удаление с сохранением данных
 Интеграция с существующими шаблонами
 Валидация бизнес-правил (1 черновик на пользователя)
